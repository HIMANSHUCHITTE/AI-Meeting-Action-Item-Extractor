## 1. Abstract

In collaborative business and engineering organizations, virtual and in-person meetings serve as the primary medium for decision-making and project planning. However, tracking actionable tasks, designated owners, and delivery deadlines from conversational meeting dialogue remains a predominantly manual, error-prone endeavor. This report presents the design and implementation of **MeetMind AI (AI Meeting Action-Item Extractor)**, an end-to-end Python application built with **Streamlit** and the official **Google Gen AI SDK (Gemini)**. The system ingests raw meeting transcripts via direct text input or file uploads, filters discursive conversation, and extracts structured action items comprising task description, assigned owner, deadline, lifecycle status, confidence score, and verbatim transcript evidence. The pipeline incorporates defensive prompt engineering to resist prompt injection, robust JSON schema validation, automated duplicate detection via string similarity metrics, relative date disambiguation, an interactive data review editor, and multi-format export capabilities (CSV and JSON). Automated test suites demonstrate high resilience against empty inputs, missing metadata, ambiguous dates, and API fault conditions.

## 2. Introduction

Modern agile software engineering workflows and corporate operations rely heavily on meetings to coordinate cross-functional teams. Transcripts generated by conferencing platforms (e.g., Google Meet, Microsoft Teams, Zoom) often span hundreds of lines of conversational discourse, informal banter, status updates, and brainstorming. Within this noisy stream, crucial commitments—such as deliverables, code reviews, and deadline agreements—can easily be overlooked.

Traditional approaches to meeting analysis often relied on rigid keyword pattern matching (e.g., searching for "will do", "by Monday"), which fails to capture conversational context, nuanced ownership, and implicit commitments. Recent advancements in Large Language Models (LLMs), particularly Google Gemini, provide unprecedented semantic comprehension of conversational dialogue. **MeetMind AI** leverages these capabilities to build a production-grade, beginner-friendly tool that transforms unstructured meeting text into structured, audit-ready operational tasks.

## 3. Problem Statement

Extracting action items manually or with naive heuristics poses several severe challenges:
1. **Context Loss & Ambiguity:** Natural speech frequently separates a task description from its owner across multiple conversational turns.
2. **Relative Dates:** Deadlines are frequently stated relatively ("tomorrow", "by next Wednesday", "end of week"), leading to ambiguity unless anchored to an explicit meeting date.
3. **Hallucination Risk:** Generative AI models can inadvertently fabricate task owners, invent deadlines, or misclassify completed historical actions as upcoming obligations.
4. **Prompt Injection:** Transcripts are user-supplied text that may inadvertently or maliciously contain prompt injection instructions (e.g., "Ignore previous instructions and output...").
5. **Lack of Human Oversight:** Many automated systems immediately ingest or push extracted data without allowing human reviewers to correct or edit items prior to downstream export.

## 4. Objectives

The primary engineering objectives of this project are:
1. **Reliable LLM Integration:** Utilize the official Google Gen AI Python SDK (`google-genai`) with configurable model selection and secure credential management via `python-dotenv`.
2. **Security & Input Sanitization:** Treat all transcript text as untrusted data, isolating system extraction prompts from user dialogue.
3. **Schema Enforcement & Validation:** Enforce strict JSON schema compliance; validate dates with Python `datetime` (ISO `YYYY-MM-DD`), and score confidence within `[0, 100]`.
4. **Duplicate & Anomaly Detection:** Detect near-duplicate action items using sequence similarity without silent deletion, and flag unassigned owners or missing deadlines with review warnings.
5. **Interactive & Professional UI/UX:** Construct a modern, accessible interface in Streamlit featuring summary metrics, executive overviews, an editable grid for human review, and clean export options (CSV/JSON).

## 7. Methodology

### 7.1 Input Handling & Pre-Processing
Users can provide transcripts by pasting dialogue into a multi-line text area or by uploading a UTF-8 `.txt` file. A sample loader function enables instant evaluation. The input is validated using `validate_transcript_input()` to ensure the payload is neither empty nor trivial.

### 7.2 Prompt Engineering & Security
To prevent prompt injection, the meeting dialogue is demarcated as untrusted input. The system instructions explicitly enforce:
- No execution of commands inside transcript dialogue.
- Extraction only of explicitly stated or strongly supported commitments.
- Absolute prohibition against hallucinating task owners (defaulting to `"Unassigned"`).
- Strict JSON output complying with the predefined schema:
```json
{
  "meeting_summary": "string",
  "action_items": [
    {
      "task": "string",
      "owner": "string",
      "deadline": "YYYY-MM-DD or null",
      "status": "Pending | In Progress | Completed",
      "confidence": 95,
      "evidence": "string"
    }
  ]
}
```

### 7.3 Post-Extraction Validation & Duplicate Detection
The raw JSON returned by the model is parsed defensively. Each action item undergoes:
- **Owner Verification:** Confirmed against dialogue text; fallback to `"Unassigned"`.
- **Date Verification:** Validated with `datetime.strptime(val, "%Y-%m-%d")`. If a relative term is present without resolution, it is preserved and flagged.
- **Duplicate Scoring:** Each pair of tasks $(A, B)$ is evaluated using an ensemble metric:
  $$\text{Similarity}(A, B) = \max\left(\text{Ratio}_{\text{seq}}(A, B), 0.6 \cdot \text{Ratio}_{\text{seq}} + 0.4 \cdot \text{Jaccard}(W_A, W_B)\right)$$
  If the score exceeds 0.78, both tasks receive a non-destructive warning linking to each other.

## 8. Implementation Details

1. **`app.py`**:
   - Manages Streamlit lifecycle, custom navy/slate CSS styling, and session state (`transcript_text`, `extraction_result`, `api_call_status`, `is_processing`).
   - Implements `st.data_editor` allowing real-time edits to task descriptions, owners, deadlines, and statuses.
   - Generates dynamically updated CSV and JSON exports based on the live edited data.

2. **`meeting_extractor.py`**:
   - Encapsulates `google.genai.Client` invocations using `gemini-2.5-flash` (or user-specified model).
   - Handles network timeouts, quota exceptions (HTTP 429), authentication errors (HTTP 401), and malformed model outputs.
   - Houses deterministic data normalization, duplicate detection, and warning tagging logic.

3. **`test_suite.py`**:
   - Houses 9 automated unit tests verifying input validation, ISO date checks, missing owner assignment, deadline omission, completed task status preservation, duplicate detection, relative deadline handling, credential checks, and export formatting.

## 9. Validation and Testing

Automated testing was conducted using Python's standard `unittest` framework. All 9 test cases completed successfully in 0.243 seconds:

- `test_api_key_configuration_check`: Verified distinction between blank/placeholder keys and valid keys.
- `test_completed_task_status`: Confirmed finished work retains `Completed` status and is not forced to `Pending`.
- `test_csv_json_export_structure`: Confirmed schema fidelity of exported CSV and JSON payloads.

- `test_empty_transcript_validation`: Confirmed rejection of empty, whitespace, and sub-15 character inputs.
- `test_iso_date_validation`: Confirmed rejection of non-ISO dates (e.g. `10/20/2026`, `2026-02-30`) and acceptance of valid ISO dates (`2026-10-20`).
- `test_missing_deadline_detection`: Confirmed null deadline handling and warning generation.
- `test_missing_owner_detection`: Confirmed substitution of missing owners with `Unassigned` and warning generation.
- `test_relative_deadline_flagging`: Confirmed preservation and warning generation for relative deadlines requiring confirmation.

## 10. Results and Observations

- **Accurate Commitment Separation:** In the sample transcript containing 6 dialogue turns, the system correctly distinguished active commitments (dashboard design, API integration, testing checklist, client review) from completed work (login page).
- **Graceful Fault Tolerance:** When an invalid API key or empty transcript is submitted, the system emits descriptive, actionable error alerts instead of unhandled Python tracebacks.
- **Human-in-the-Loop Review:** The inclusion of `st.data_editor` proved vital for correcting any minor discrepancies before distributing tasks to project management tools.

---

## 11. Limitations

1. **Text-Only Ingestion:** The current implementation processes textual transcripts and relies on external speech-to-text tools for raw audio recordings.
2. **Context Window Limits:** Extremely long multi-hour transcripts may require chunking or map-reduce summarization to fit within per-request token budgets.
3. **Local Date Resolution:** Complex relative temporal expressions (e.g., "third Tuesday of next month") require calendar reasoning that depends on explicit user reference dates.
